# Vulnerability feed (v1: Wordfence Intelligence, sync-and-match)

Every site's stored plugin/theme inventory gets matched against the free Wordfence Intelligence vulnerability database, so affected items are flagged in the dashboard. Following the decision recorded in PLAN.md: **Wordfence Intelligence v3 is the primary source** (free API key from a wordfence.com account, `Authorization: Bearer` header, paginated endpoints like `/api/intelligence-platform/v3/vulnerabilities/production`, records with `software` slug/type, affected-version ranges, `patched`, `cve`, `cvss`). Patchstack stays an optional future secondary source.

## 1. Schema

- **`vulnerabilities` table**: `source` (default `wordfence`), `external_id`, `software_type` (plugin|theme), `software_slug`, `title`, `cve` nullable, `cvss` nullable decimal, `patched` bool nullable, `patched_version` nullable, `affected_from`/`affected_to` nullable strings with `_inclusive` bools, `published_at` nullable, `raw` JSON (the full source record — keeps us resilient to schema drift), `timestamps`. Unique on `(source, external_id)`.
- **`inventory_items.vuln_count`**: nullable int — `null` = not yet checked, `0` = checked/clean, `N` = number of matching vulnerabilities.

## 2. Sync + matching (all in `app/Actions`)

- **`SyncVulnerabilityFeed`** — fetches the production feed page by page (`X-WF-Total-Pages` pagination) with the Bearer key, upserts records, deletes vanished ones, then re-runs matching. Extracts normalized fields but stores the raw record too.
- **`MatchInventoryVulnerabilities`** — re-computes `vuln_count` for every inventory item: match by `software_type` + `software_slug`, installed `version` inside the affected range(s) using PHP's `version_compare` semantics (same as WordPress), and not newer than the patched version when one exists. Runs after every feed sync and after `ProcessInventoryResult` (new inventory gets checked immediately).
- **`vuln:sync` command** — thin wrapper with a progress bar; also scheduled weekly in `routes/console.php`.

## 3. Settings + UI

- **Settings page** (owners only): new "Vulnerability feed" card — API key field (stored encrypted, same pattern as the SMTP password) and a **"Sync now"** button that queues/runs the sync with a status notification showing how many vulnerabilities were stored. Without a key, the card explains how to get one free from wordfence.com.
- **Sites table**: red "N vulnerable" badge per site (sum over its inventory).
- **ViewSite**: each plugin/theme row shows a red vulnerability badge with a tooltip listing the CVE/titles; a site-level count in the header strip. Excluded-from-updates items still show their vulnerabilities (knowing is the point — exclusions only affect updating).

## 4. Tests

- `VulnerabilitySyncTest`: fake HTTP with two pages → records upserted, stale removed, matching flags a vulnerable item at an in-range version, clean at the patched version, unknown slugs untouched; re-sync updates counts.
- `SiteActionsTest`-style UI assertions: badge visibility and counts render.
- Full suite green.

## 5. Ship

Commit/push/deploy. After deploy: paste your free Wordfence API key in Settings → "Sync now" → vulnerabilities start appearing. (I'll need a key from you, or you can create one at wordfence.com → it's free.)

**Out of scope for v1:** email alerts on new vulns (comes with digests), Patchstack as a second source, severity-based filtering UI.
